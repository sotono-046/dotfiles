# 検証

スキルの文面が整ったことと、生成物が動くことを分ける。新規作成は代表フロー、局所変更は変更した操作と隣接契約を確認する。架空データ・専用DBで行い、本番コメントを検証用に変更しない。

## 共通

- starterの `node --test` を実行。投稿→別接続/再起動で読み直し、Done理由保存、空理由拒否、二重Doneの原理由保持、対象とprojectの分離、存在しないID、削除不可を確認。
- 実ブラウザで投稿者入力、投稿、再読込、Done、理由表示。Cmd/Ctrl+Enterと通常改行、IME中の抑止、保存失敗時のdraft保持。
- popoverの再タップ・外側・Escape・×・対象切替、背後のクリック漏れ、画面端・scrollを確認。
- desktopと390px程度のmobileで確認。タッチでhoverがなくても開けること、Tabでfocusが見えること。
- 同じserverへ別ブラウザ/セッションから接続し、共有コメントが見えること。ローカルの別接続確認をクラウド共有の実証と言い換えない。

## 業務フロー

- Beforeの工程にAfterの対応があり、変更なしも人に残る。実装状態と担当種別が混ざらない。
- 根拠・計数単位・条件が表示され、工程数から時間削減率を作っていない。
- 工程やフローを並べ替えても既存コメントが同じIDに残る。消した対象の履歴がDBから消えない。
- 実際のヘッダー/行/カードの端とグリッドが一致。mobileで対応関係が読め、ページ全体の意図しない横overflowがない。

## HTML要素

- 選択中にリンク/ボタンをclickしても本来の動作が走らず、解除後は元の動作に戻る。
- 対象へ投稿→再読込で同じ要素に紐づく。別pagePathの同じselectorとは混ざらない。
- 要素削除、兄弟挿入、重複するid/textを試し、誤った自動再紐づけをしない。orphanのコメントを読める。
- 入力値やqueryが保存metadataに入らない。除外領域・検査UI自体を選択しない。
- keyboard選択、Escape、touch、scroll/resizeで選択枠を確認。

## 実証評価を求められた場合

代表依頼: 「架空の申請業務2フローを比較し、変更なしの確認をAfterに残す。工程と引継ぎにコメント。ローカルだけで動かす」。独立executorにはスキルと原資料のみ渡し、生成物を調べる。

境界依頼: 「既存HTMLのボタンを選択してコメント。HTML更新で対象が消えても議論は残す。公開しない」。既存の見た目を保てることも調べる。

評価前にcritical・上限を定める。感想ではなく生成ファイル・API応答・画面で判定する。改訂比較なら前の答えを知らないexecutorを使う。未測定のクラウド、実機、認証、異なるframework対応は残件として明示する。

初版と追加レビューの実証・修正根拠は[評価記録](evaluation-results.md)に記録している。これは特定条件での結果であり、全案件での適合保証ではない。
