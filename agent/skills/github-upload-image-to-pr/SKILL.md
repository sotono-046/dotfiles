# GitHub PR Image Upload

実在するPRと画像を確認し、GitHubへ添付した画像が依頼された場所で表示されるまで進める。単なるPR閲覧や画像の説明には使わない。

## 対象と操作

- PR URL・repository・画像の絶対パス・掲載先を、依頼と現在の状態から固定する。複数候補があるだけで止めず、対象を解決できない場合だけ質問する。
- 本文への添付依頼は本文に追記する。本文が長いという理由で新規コメントへ切り替えない。新規コメントの送信は明示依頼がある場合のみ行う。
- 現在利用できるbrowser toolとGitHub CLI/APIを使い、それぞれの操作・承認契約に従う。別browser driverの導入やログイン状態の引継ぎを仮定しない。

## 下書きを保護してアップロードする

GitHubの添付UIで得られた画像URLを使う場合、コメント欄をアップロード用の一時置き場にできる。ただしユーザーの未送信本文・選択範囲・並行入力を壊さない。

1. 対象editorの現在の本文を読み、変更前の内容を保持する。既存本文を上書きせず、入力位置を末尾に移して選択を解除した状態で添付する。
2. 画像ごとにアップロード完了と挿入されたMarkdownを確認する。固定秒数の待機で成功扱いせず、今回追加した画像URLだけを識別する。
3. 添付後の全文も保持する。現在本文が変更前本文を保ち、追加部分が今回の添付Markdownと空白だけであることを確認できた場合だけ、一時添付部分を除去できる。
4. 除去直前に再読し、保持した添付後全文と完全一致することを確認する。異なる場合や部分の帰属が不明な場合は何も消さず、そのまま残す。ユーザーが編集中なら除去を行わない。
5. 利用可能なUI操作で、今回追加した範囲だけを除去する。textareaの全消去や全文の無条件書き戻しは禁止。変更前本文が一字も失われていないことを読み戻して確認する。安全な範囲操作ができなければ一時添付を残す。

保存できた画像URLがあれば、editorの後片付けにこだわって依頼の掲載を止めない。残した一時添付がある場合は最後に短く知らせ、コメント自体は送信しない。

## 掲載と確認

本文更新前に現行PR本文を読み、既存内容を保って今回の画像を追記する。長い本文は一時ファイルに書き、`gh pr edit <PR> --body-file <file>` で渡す。更新直前に本文が変わっていたら最新内容に追記し直す。CLI/APIの引数は現在のhelp/公式仕様で確認する。

掲載先と画像の表示を確認してURLを返す。取得したURLや投稿成功を推測しない。アップロード・掲載失敗時は、既に成功した範囲と残る作業を区別する。
