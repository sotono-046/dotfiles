# 結果を一度だけ通知する

通知する条件は共通方針の「結果の通知」に従う。スキルを読んだだけでは通知を許可されたことにならない。通常の最終回答・内部報告はそのまま行う。

## 対象とタイミング

ユーザーが今回の作業について通知を明示した場合は `--request result`、リーダーに指名した場合は `--request leader --role leader` を使う。静かに進める指示があれば通知しない。配下のworkerは通知せず、Orcaの `worker_done` や質問などの内部報告を続ける。

依頼を受けた時に、その依頼専用のIDを決めて作業コンテキストへ残す。Orca Run IDとユーザー依頼IDの組み合わせ、または新しいUUIDを使い、同じ依頼の再開でも維持する。branch名・terminal名・repo名だけのIDは次の依頼と衝突するため使わない。

成果物と必要な検証を確認してから通知する。リーダーは対象の作業すべての結果を確認してまとめる。応答終了・idle・子の終了は通知の契機にしない。失敗で依頼を終える場合は、失敗と残件を記載する。質問が必要な途中段階では、通常の会話や内部メッセージで質問する。

本文は作業名、結果の要点、成果物のpathまたはURLを短くまとめる。秘密情報や個人情報を入れず、OS通知からリンクを開けるとは約束しない。

## 通知する

`<skill-dir>` はこのSKILL.mdがあるdirectoryに置き換える。次は実行例であり、通知の許可ではない。

```bash
python3 <skill-dir>/scripts/notify_result.py \
  --task-id '<今回の依頼ID>' --request result --role owner \
  --title '作業名：完了' \
  --message '検証済みの結果。成果物: /absolute/path または URL'
```

実通知を出さずに確認する場合は `--dry-run` を付ける。依頼IDの履歴も更新しない。workerは `--role worker` で抑制され、`--request` を省略した呼び出しも通知しない。

macOSでは標準の `osascript` を使い、明示的な結果通知だけに `Hero` サウンドを付ける。Linuxでは既にある `notify-send` を使う。packageの追加・外部サービスへの送信は行わない。実行hostのローカル通知であり、Mac miniからMacBookやスマートフォンへ転送する機能はない。別端末への通知は、その経路が明示的に依頼・設定されている場合に限って扱う。

返るJSONの `submitted` はOSへの送信受付を示す。画面表示やユーザーが見たことの証拠にはしない。OSの通知許可や集中モードによって表示されないことがある。重複は抑制され、失敗・timeoutも同じIDで自動再送しない。送信できなければ会話で結果と通知の失敗を伝える。

履歴は `~/.local/state/agent-result-notify/` に保存する。通知後は今回の通知指定を終了し、次の依頼に引き継がない。テストでは `--state-dir` を一時directoryに指定する。

## 自動通知を抑える設定

Orca・Claude自身の自動通知はこのスクリプトでは止められない。[設定と配信の手順](references/quiet-notifications.md) を読む。状態報告hookや内部通信を削除して通知を抑える方法は使わない。
