# IP as Logo

32pxでも分かる、丸く単純なキャラクターロゴを作る。一般的なキャラクターイラストや既存UIの改修には適用しない。

- ユーザーの主題・個数・palette・参照画像を優先する。単一ロゴなら1案を生成し、候補比較を求められた場合だけ複数案を作る。十分なbriefがあれば生成前の承認段階を増やさない。
- 主題が未指定なら、必要な製品情報から根拠のある方向を選ぶ。目的や対象が決められない場合だけ不足点をまとめて質問する。
- [形状・色・prompt](references/style-and-prompt.md)の今回必要な節を読む。既定は大きな連続シルエット、IPの2色＋背景1色、弱い内部陰影。明示された別スタイルは優先する。
- 実行環境で利用可能な画像生成toolを使い、その入力schemaと編集方法に従う。未提供のmodel/parameter/並列処理を前提にしない。
- 複数案は個別assetとして出し、依頼に含まれないcontact sheetや6案一式を既定にしない。
- 実際の画像でシルエット、識別特徴、色分離、背景と可読性を確認する。必要な局所修正を行い、未達条件を隠す後処理をしない。
- 生成物を表示し、保存先・候補の違い・残る制約を必要な範囲で伝える。ユーザーの選択待ちは、選択が次の作業に必要な場合だけにする。
