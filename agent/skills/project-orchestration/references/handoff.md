# Listenerからの引き継ぎ

引き継ぐ直前に中心ノートを読み直す。既存の資料を上書きせず、日時または重複しないIDを付けたMarkdownを `handoffs/` へ保存する。保存先は [project-notes.md](project-notes.md) に従う。

以下の項目を、その作業に必要な範囲で埋める。未確定の項目を推測で完成させない。

```markdown
# 引き継ぎ <ID>

- プロジェクト名:
- 中心ノートのパス:
- 作成日時:
- 参照したノートの版: 更新日時または内容のハッシュ
- 進める範囲: 相談 / 計画 / 実行
- 許可の根拠: 今回のユーザー依頼と既に確認した指示
- 状態: 準備済み

## 目的と完了条件

## 決定事項と理由

## 制約と対象外

## 未決事項と提案

## 次に依頼すること

## 入力資料
```

受け手が読めるパスや添付形式を確認する。渡せないローカルパスだけを送って引き継ぎ完了としない。秘密情報や作業に不要な個人情報を丸ごと複製しない。

保存後は資料の本文を固定する。後の変更は新しいIDの資料にし、どの版を置き換えるかを記す。中心ノートには保存した資料へのリンクを追加する。

作成と送信は分けて記録する。作業計画だけを頼まれた場合は、準備済みで止める。実際に担当へ渡したときは、資料のID、相手、依頼の識別子を中心ノートや作業記録に追記する。返答が確認できた場合だけ受領済みとする。固定した資料の「準備済み」を後から書き換える必要はない。

実行中に目的や制約が変わったら、進行中の担当へ変更を伝え、古い条件での新規着手を止める。既存の成果物や報告は消さず、どの版で作られたかを残す。変更の影響がない作業は続ける。
