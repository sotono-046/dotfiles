# プロジェクトの保存先

## フォルダと中心ノート

ユーザーが指定したパスを優先する。新しく保存先を作るときは、1プロジェクト1フォルダと、その中の中心ノート1枚を推奨する。ファイル名だけでも対象が分かるよう、中心ノートにプロジェクト名を使う。

```text
project/
  project-name/
    project-name.md
    handoffs/
    references/
```

`handoffs/` は引き継ぎ時、`references/` は資料を保存するときに作る。空のフォルダを先に量産しない。中心ノートから必要な資料へリンクし、再開のたびに過去ログ全部を読む構成にしない。

既存の `project/project-name.md` という配置でも使える。ユーザーが明示したファイルを、別の場所へ黙って移さない。この配置で引き継ぎ資料を残す場合は `project/project-name/handoffs/` を使い、中心ノートの場所は維持する。

このユーザーが指定した保存先は `/Users/sotono/Library/CloudStorage/Dropbox/Mitumine/_agent/project/`。その直下の `aino_MIRAI.md` は「AINOのMIRAI」の専用ノートである。他のプロジェクトや汎用スキルの開発記録を書かない。これはローカル環境の指定であり、別の環境へ存在しないパスを作らない。

## 対象を選ぶ

明示されたファイルがあればそのファイルを読む。名前だけなら、指定フォルダのファイル名から候補を絞り、表題やプロジェクト識別子を確認する。同名候補や移行前後のファイルが並び、今回の対象を一意に決められないときだけ尋ねる。全プロジェクトの本文を一括で読み込まない。

フォルダとファイル名を作るときは、既存の命名規則とユーザーの表記を優先する。既存ファイルを新規テンプレートで置き換えない。指定ノートが空なら、確定しているプロジェクト名から始め、内容が未提示の見出しを埋めない。

## Listenerの読み込み

選んだプロジェクト名と中心MDの絶対パスを会話の引き継ぎに残し、各ターンでそのファイルを読む。ユーザーから対象や保存先の変更があれば反映する。AINOのMIRAIでは現在指定されている `/Users/sotono/Library/CloudStorage/Dropbox/Mitumine/_agent/project/aino_MIRAI.md` を読む。

回答や作業判断に入る前に、ツールで本文の最新内容を読み取る。人が追記した内容や変更した決定を今回の発言と照合し、現在のユーザー指示を優先する。同じターンの開始時に読めていれば、その読み込みを使える。保存する場合は「保存と競合」の手順で直前にも読み直す。

指定済みのノートが見つからない、または読めない場合は、パスと読み込めなかった事実を短く伝える。最新版を読んだとは報告せず、その内容を必要としない相談や作業は続ける。推測した内容で決定や上書きをせず、代わりのノートを勝手に新規作成しない。空のファイルを読めた場合は、未記入として扱う。

## ノートの内容

既存の構成を優先する。初めて作る場合は、必要な節だけ次の例から使う。

```markdown
# プロジェクト名

## 現在の目的

## 決定事項と理由

## 制約と対象外

## 未決事項と提案

## 作業状況と次の一歩

## 参照資料と引き継ぎ

## 更新履歴
```

決定には分かる範囲で日付と出典を添える。出典はユーザー発言、資料のパス、会話URLなど、実際に確認したものを使う。発言日時が不明なときは記録日時と区別する。変更された決定は現在の節を更新し、履歴に変更前後と理由を短く残す。昔の履歴を新しい決定だったように書き換えない。

未決事項には、何が未定で、どの作業に影響するかを記す。提案したことだけを根拠に「採用」としない。技術案と利用者の目的を混ぜない。

## 保存と競合

1. 保存前に最新の内容を読み直す。最初に読んだ内容との差分と、ユーザーの手書き箇所を確かめる。
2. 変更する節だけ更新する。既存のfrontmatter、独自見出し、自由記述、リンクは維持する。
3. 編集ツールの一致条件や元の内容の照合を使い、読み取った版にだけ変更を適用する。途中で変わっていたら再読込し、自分の変更と無関係な編集を残して差分を組み直す。
4. 保存したファイルを読み、意図した変更と残す内容を確認してから「保存済み」と報告する。

同じ箇所の意味が衝突し、自動で統合できない場合は上書きせず、差分案と衝突箇所を残す。保存できなければ未保存と伝え、再適用できる内容を返す。古いセッションの全文で置き換えない。

Dropboxなどの同期フォルダでも、複数の書き手の排他制御を保証したとは扱わない。中心ノートの更新者を1人にし、競合コピーを見つけたら内容を確認する。同期完了やObsidian画面への反映は、ファイル保存とは別に確認したときだけ報告する。
