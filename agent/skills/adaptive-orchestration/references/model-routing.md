# 固定配役表

ユーザーが指定した配役。今回のユーザー指定 > この表の順で適用し、価格や評判から実行ごとに別モデルへ変更しない。人数とタスク分割は仕事に合わせる。

| 役割 | モデル指定 | 担当範囲 |
| --- | --- | --- |
| 司令塔・最終統合 | Sol（`gpt-5.6-sol`） | 目標、認可、分解、配信、実行状況、成果物の統合を管理 |
| 作業・実装・修正・テスト | Luna（`gpt-5.6-luna`）、reasoning effort `high` | 調査、実装、リファクタリング、テスト追加・実行・失敗修正 |
| 独立レビュー | Astra（`gpt-6-astra`） | Lunaの成果を要件・差分・検証証拠に照らして検証。修正はせずSolへ返す |
| デザイン相談 | Claude Opus 5.5 と Fable（`claude-fable-5`） | UI/UX、レイアウト、ビジュアル、操作感について独立案を返す。Solが統合し、製品コードはLunaが実装 |

Lunaの`high`は必須。他モデルのeffortは追加指定がなければruntimeの既定を使う。native toolのmodel/reasoning引数、またはinstalled helpで確認したCLI設定を使い、プロンプトに「High」と書くだけで設定済みと扱わない。

Opus 5.5はinstalled Claude CLIまたは接続済みtoolが示す正確なmodel IDを使う。`opus` aliasが5.5を指すと確認できた場合だけ利用し、別versionへ解決されるaliasや推測したslugで代用しない。

## デザイン相談

視覚・操作デザインの判断が成果を左右するときだけ、Opus 5.5とFableの両方へ相談する。色値や文言の指定どおりの置換など、判断不要な変更では追加起動しない。

1. 同じ目標、既存画面・design system、制約、変更対象を両者へ渡し、相手の答えを見せずに独立案を求める。呼び出し元自身がOpus 5.5またはFableでも、その役は別コンテキストで起動する。
2. Solが両案を既存実装と要件に照らし、採用する方向、具体的な仕様、未解決点を統合する。多数決やモデル名を根拠にしない。
3. Lunaへ実装可能な仕様として渡し、実装後はAstraが要件と証拠に基づいて独立レビューする。実画面にデザイン判断を伴う再確認が必要なら、Opus 5.5とFableの両方へ依頼する。

既定は独立案1回とSolによる統合まで。相互討論や追加roundは、完了条件を左右する未解決点が残る場合だけ行う。

## 担当の境界

- Solは司令塔として作業分割、入力補完、進捗、採否、最終統合を持つ。原則としてLunaの実装やAstraの独立レビューを兼任しない。
- コード変更は規模によらずLuna Highへ渡す。独立したscopeだけ複数のLunaへ分け、同じpathは直列化する。
- AstraはLunaの成果をread-onlyでレビューし、blockerと任意改善を分けてSolへ返す。自己修正やLunaとの直接fix-loopは行わない。
- デザインを伴う開発はOpus 5.5とFableの知見をSolが統合し、Lunaがコードにする。一般的な実装判断へデザイン相談を拡張しない。

## 固定モデルが使えない場合

モデル・必要なeffort・契約枠・override権限を確認し、利用できない指定と理由を伝える。自動で別モデルや有料経路へ置換しない。

今回の固定配役を満たせない担当部分は未完了として、実行経路の復旧または代替モデルの指定が必要なことを示す。片方しか使っていないデザイン相談を「Opus 5.5とFableへ相談済み」と報告せず、Astra以外のレビューを指定担当の完了として扱わない。
